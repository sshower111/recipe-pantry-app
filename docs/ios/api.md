# Recipe API contract (for the iOS app)

The FastAPI server in `api/app.py` is the app's only data source. Everything below was
generated by running that code (`create_app`) against a throwaway database with made-up
recipes, so field names, types and nulls are exactly what the app will receive.

## Conventions

- JSON keys are `snake_case`. Decode with `JSONDecoder.keyDecodingStrategy = .convertFromSnakeCase`
  (so `thumbnail_url` -> `thumbnailUrl`, `raw_name` -> `rawName`).
- **Anything shown as `null` in a sample can be null.** Make those properties optional.
  `amount` is a JSON number that may be fractional (`0.5`): use `Double?`.
- `thumbnail_url` is a **path**, not a full URL: prepend the server base URL
  (`http://<mac>.local:8000` + `/api/recipes/1/thumbnail`). It is `null` when there is no image.
- `steps[].ingredients` are **indexes into that recipe's `ingredients` array** (0-based), the
  lines that step mentions. Text matching, so a step like "Combine wet and dry" has `[]`.
- `steps[].short_text` is a model-written version of about 40-60 characters for the Dynamic
  Island and Lock Screen ("Mix the sauce ingredients"); show `text` everywhere else. It is
  `null` until `python main.py shorten-steps` has run on the PC for that recipe, and for a step
  the model couldn't shorten, so fall back to shortening `text` on the phone.
- `GET /api/recipes` returns only `status == "ready"` recipes by default. `?status=todo`
  (recipe is elsewhere: blog, bio link) and `?status=all` exist; the app only needs the default.
- Errors are HTTP status codes with `{"detail": "..."}` (404 for an unknown recipe).
- Step progress (which step, which are done) is **not** stored on the server; keep it on the
  phone. `favorite` / `tried` are stored on the server (`PATCH`).
- There is **no cook time** in the data (posts rarely state one and the parser doesn't extract
  it). Cards show "N ingredients · M steps" instead; don't invent a time.

## What the real data looks like (as of 2026-11-03)

89 ready recipes, all from Instagram. 71 have no `yield_label`; 14 have no steps yet (run
`python main.py reparse --missing-steps` on the Mac to fill them); every one has a thumbnail
and an uploader, but the schema allows null for both. 280 of 921 ingredient lines have no
`amount`. The longest method is 20 steps.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/recipes` | Cookbook list (`?status=ready\|todo\|all`, default `ready`) |
| GET | `/api/recipes/{id}` | One recipe with ingredients, steps (+ step ingredient indexes), video |
| PATCH | `/api/recipes/{id}` | Set `{"favorite": bool}`, `{"tried": bool}`, `{"hidden": bool}` and/or `{"status": "needs_recipe" \| "not_recipe"}`; returns all four |
| GET | `/api/recipes/{id}/thumbnail` | The image (JPEG/PNG/WebP); 404 if none |
| GET | `/api/ingredients` | Canonical ingredient names used by ready recipes, most used first |
| GET | `/api/pantry?have=a&have=b` | Recipes using what you have (repeat `have`); `limit`, `include_staples` |
| POST | `/api/ingest` | `{"url": "<link or text containing one>", "refresh": false}`: queue a post to add; 202 with the job |
| GET | `/api/ingest` | Recent jobs, newest first (in memory: a uvicorn restart clears them) |
| GET | `/api/ingest/{job_id}` | One job; poll it until `status` is `done` or `failed` |

**Adding recipes (share sheet).** The PC runs jobs one at a time on a background thread, the
same pipeline as `main.py ingest --skip-existing` (a post already stored finishes at once with
`result: "skipped"`). Sharing the same post again while its job is queued or running returns
that job. A job looks like:

```json
{"id": "3f9c2a1b7d4e", "url": "https://www.instagram.com/reel/ABC/", "status": "done",
 "created_at": "2026-11-03T20:15:02+00:00", "finished_at": "2026-11-03T20:17:10+00:00",
 "recipe_id": 116, "title": "Garlic Noodles", "result": "added", "recipe_status": "ready",
 "message": null}
```

`status`: `queued` | `running` | `done` | `failed` (`message` says why). `result`: `added` |
`updated` | `skipped`. `recipe_status`: `ready` (has ingredients), `needs_recipe` (the post
points elsewhere; `message` may say why the page failed) or `not_recipe`. 422 when the text has
no link; 503 when the server runs without the pipeline (tests). `"refresh": true` re-downloads
a stored post (the app's "Check again"); a post saved as `needs_recipe` stays `needs_recipe`
if it still has no list.

Pantry search normalizes on the server ("2 large eggs" -> `egg`), so send what the user typed.
Staples (salt, black pepper, water, oil) are ignored unless `include_staples=true`. Results
rank by most selected ingredients used, then fewest others needed.

## Suggested Swift models

```swift
struct RecipeSummary: Codable, Identifiable, Hashable {
    let id: Int
    let title: String
    let uploader: String?
    let yieldLabel: String?
    let status: String?
    let ingredientCount: Int
    let stepCount: Int
    var favorite: Bool
    var tried: Bool
    let thumbnailUrl: String?
    let platform: String?        // "instagram" | "youtube" | "tiktok" | null
}

struct Recipe: Codable, Identifiable {
    let id: Int
    let title: String
    let uploader: String?
    let description: String?
    let yieldLabel: String?
    let status: String?
    var favorite: Bool
    var tried: Bool
    let thumbnailUrl: String?
    let recipePageUrl: String?
    let video: Video
    let ingredients: [Ingredient]
    let steps: [Step]
}

struct Video: Codable { let url: String; let platform: String?; let embedUrl: String? }

struct Ingredient: Codable, Hashable {
    let name: String             // canonical, e.g. "butter"
    let rawName: String          // as written, e.g. "unsalted butter" -- show this
    let amount: Double?
    let unit: String?
}

struct Step: Codable, Hashable {
    let text: String
    let shortText: String?       // island version; null until shortened
    let ingredients: [Int]       // indexes into Recipe.ingredients
}

struct Marks: Codable { let favorite: Bool; let tried: Bool }

struct PantryIngredient: Codable, Hashable { let name: String; let recipeCount: Int }

struct PantryMatch: Codable, Identifiable {
    var id: Int { recipeId }
    let recipeId: Int
    let title: String
    let thumbnailUrl: String?
    let matched: Int
    let selected: Int
    let total: Int
    let missingCount: Int
    let have: [String]
    let missing: [String]
}
```

Display rules the web app uses (match them): amounts as fractions (`0.5` -> `½`, `1.5` ->
`1½`, `0.333` -> `⅓`; see `web/lib/api.ts::formatAmount`), label = amount + unit + `rawName`
with the first letter capitalised, captions with `#hashtags` stripped.

### `PATCH /api/recipes/1  {"tried": true}`

```json
{
  "favorite": true,
  "tried": true,
  "hidden": false,
  "status": "ready"
}
```

`hidden: true` is the app's swipe-to-remove: the recipe leaves `GET /api/recipes`, pantry
results and `/api/ingredients` but stays in the database (a user mark, like `favorite`;
re-ingesting never resets it), so `hidden: false` undoes it. `GET /api/recipes/{id}` still
answers for a hidden recipe.

`status` relabels a post **without** an ingredient list: `needs_recipe` keeps it in the app's
Saved list (`GET /api/recipes?status=todo`; the recipe is elsewhere or still coming),
`not_recipe` hides it. A recipe with ingredients answers 409 (it is always `ready`).
